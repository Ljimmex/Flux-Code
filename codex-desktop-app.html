AI Code Assistant Desktop App

Kompletny design, stack technologiczny (Tauri v2) i szczegółowy roadmap dla aplikacji typu T3 Code / Codex

1. Wprowadzenie i Cel Aplikacji

Cel dokumentu

Niniejszy dokument stanowi kompletny blueprint do stworzenia desktopowej aplikacji AI Code Assistant — narzędzia, które będzie Twoim prywatnym, lokalnym centrum dowodzenia do pracy z agentami AI kodującymi. Aplikacja jest inspirowana T3 Code (Theo) i OpenAI Codex App, ale budowana od zera jako Twoje własne rozwiązanie.

Dla kogo jest ta aplikacja

Dla Ciebie — solo developera, który chce mieć własne, prywatne narzędzie do pracy z AI kodującym. Nie zależy Ci na SaaS, subskrypcjach czy cloudzie. Chcesz aplikację desktopową, która:

  • Działa lokalnie na Twoim komputerze (z możliwością cloud API gdy chcesz)
  • Łączy się z Twoimi własnymi kluczami API (BYOK — Bring Your Own Key)
  • Pozwala pracować nad wieloma projektami Git równocześnie
  • Izoluje zmiany AI w Git worktree (nie brudzi Twojego głównego workspace)
  • Pozwala uruchamiać wielu agentów równolegle na różnych zadaniach
  • Ma zintegrowany diff viewer do review zmian
  • Ma zintegrowany terminal do komend

Philosophia aplikacji

"Twoje AI, twoje klucze, twój kod, twoja maszyna." Aplikacja nie jest kolejnym SaaSem, który musisz subskrybować. Jest to lokalne narzędzie desktopowe — jak VS Code czy Terminal — które instalujesz raz i używasz bez ograniczeń. Płać tylko za API LLM (OpenAI/Anthropic) lub używaj darmowych lokalnych modeli (Ollama). Żadnych monthly fees, żadnych limitów, żadnego vendor lock-in.

Form factor — Desktop App

Aplikacja jest natywną aplikacją desktopową (nie webówka, nie PWA):

  • Okno główne: trzy-panelowy layout (projekty | wątki | chat)
  • Multi-window: można otworzyć wiele okien (np. diff w osobnym oknie)
  • System tray: działa w tle, szybki dostęp
  • Global shortcut: Cmd + Shift + C (macOS) / Ctrl + Shift + C (Win/Linux) do otwarcia z dowolnego miejsca
  • Auto-updater: aktualizacje bez reinstallu
  • Bundle size: ~10-15 MB (vs 150MB+ Electron)

2. Design Aplikacji — Co Powinna Zawierać

Ta sekcja szczegółowo rozpisuje każdy element designu aplikacji — od ogólnego layoutu po najmniejsze komponenty. To Twój przewodnik po tym, co ma być zaimplementowane.

2.1. Architektura Okna i Layout

Główne Okno — Three-Panel Layout

Aplikacja opiera się na trzech panelach podobnie jak T3 Code:

  • Lewy panel (SIDEBAR): lista projektów + nawigacja główna (min 200px, max 350px, resizable)
  • Środkowy panel (THREADS): lista wątków/konwersacji dla wybranego projektu (min 250px, max 400px, resizable)
  • Prawy panel (MAIN): obszar roboczy — chat, diff viewer, terminal (reszta dostępnej przestrzeni)

Wszystkie panele są resizable (drag divider) i collapsible (można zwinąć każdy panel do ikon).

Top Bar (Header)

Pasek na samej górze okna (nad panelami):

  • Lewa strona: nazwa aplikacji + ikona, aktualny projekt (breadcrumb)
  • Środek: nazwa aktywnego wątku, wskaźnik statusu agenta (idle/running/waiting)
  • Prawa strona: selector modelu (dropdown), przycisk nowego wątku, przycisk ustawień (gear), przycisk minimalizacji/zamknięcia (native window controls)

Bottom Bar (Status Bar)

Pasek statusu na dole okna:

  • Lewa strona: status połączenia (online/offline), wersja aplikacji
  • Środek: aktualnie używany model (np. "gpt-5.2-codex"), liczba aktywnych agentów
  • Prawa strona: token usage (input/output), koszt sesji (USD), liczba plików w kontekście

Native Window Controls

  • macOS: traffic lights (zamknij/minimalizuj/maksymalizuj) po lewej, przezroczyste tło, vibrancy effect
  • Windows: standardowe przyciski po prawej, Mica/Acrylic material
  • Linux: standardowe GTK decorations, dark theme default
  • Keyboard shortcuts:
    • Cmd/Ctrl + , — ustawienia
    • Cmd/Ctrl + N — nowy wątek
    • Cmd/Ctrl + Shift + N — nowy projekt
    • Cmd/Ctrl + T — nowy wątek
    • Cmd/Ctrl + W — zamknij wątek
    • Cmd/Ctrl + B — pokaż/ukryj sidebar

2.2. Panel Projektu (Sidebar)

Sekcja Projekty

Lewy sidebar zawiera:

  • Przycisk "Add Project": otwiera dialog (modal) do dodania projektu — można wybrać folder przez systemowy file picker lub wkleić ścieżkę absolutną
  • Lista projektów: każdy projekt to "card" z:
    • Favicon/ikonka (z repozytorium lub generowana z pierwszej litery nazwy)
    • Nazwa projektu (bold)
    • Ścieżka (truncated, szary kolor)
    • Branch (np. "main", badge z kolorem)
    • Liczba aktywnych wątków (badge)
    • Status ostatniego wątku (checkmark, spinner, lub kropka)
  • Aktywny projekt jest podświetlony (primary color background + border-left)
  • Kontekstowe menu (prawy przycisk myszy): Open in Finder/Explorer, Remove from list, Refresh git status, Open in VS Code

Sekcja Nawigacji (poniżej projektów)

  • Skills: ikona + napis, prowadzi do managera skilli
  • Settings: ikona + napis, prowadzi do ustawień aplikacji
  • separator (linia)
  • Help & About: ikona + napis

2.3. Panel Wątków (Thread List)

Header Panelu Wątków

  • Nazwa projektu (bold) jako tytuł panelu
  • Przycisk "New Thread": plus icon, tworzy nowy wątek
  • Przycisk "Quick Actions": play icon, lista zdefiniowanych akcji
  • Search bar: filtrowanie wątków po nazwie/treści (debounced)

Lista Wątków

Każdy wątek to "card" z:

  • Ikona statusu: spinner (running), checkmark (completed), clock (pending), chat bubble (chat mode)
  • Tytuł wątku: auto-generowany z pierwszego promptu (np. "Add authentication middleware") lub manualnie edytowany
  • Podtytuł: data ostatniej aktywności (relative: "2 min ago") lub model użyty
  • Badge trybu: "Chat", "Plan", "Worktree" — kolorowe etykiety
  • Status PR: jeśli wątek zakończył się PR, pokazuje status (open/merged/closed) z ikonką GitHub

Grupowanie wątków

  • "Running" (aktywne, na górze)
  • "Today"
  • "Yesterday"
  • "This Week"
  • "Older"

Kontekstowe Menu Wątku

  • Rename
  • Duplicate (kopiuj wątek z tą samą konfiguracją)
  • Archive
  • Delete (z potwierdzeniem)
  • Copy link (do worktree/diff)
  • Open worktree in VS Code

2.4. Panel Chatu (Główny)

Konfiguracja Wątku (nad chatem)

Górna część panelu przed wiadomościami — konfiguracja dla tego wątku:

  • Model Selector: dropdown z dostępnymi modelami (OpenAI GPT-5.2, Claude 4 Sonnet, Claude 4 Opus, Ollama local). Zapisane per wątek.
  • Mode Toggle: Chat mode | Plan mode (przycisk toggle/tab). Chat = szybkie pytania, Plan = agent najpierw robi plan przed pisaniem kodu.
  • Access Level: Full Access | Supervised (toggle). Full = agent może pisać pliki bez pytania. Supervised = każda zmiana wymaga akceptacji.
  • Reasoning Level: slider 1-5 (ile planowania agent robi przed działaniem)
  • Worktree toggle: czy agent pracuje w izolowanym worktree

Obszar Wiadomości

Scrollowalny obszar z listą wiadomości:

  • User Message: prawo, tło primary/10, avatar usera (inicjały), treść jako markdown
  • Assistant Message: lewo, tło neutral, avatar AI (bot icon), treść jako markdown z code blocks
  • Tool Call Message: lekki styl, ikona wrench, nazwa toolu (np. "read_file: src/auth.ts"), status (running/completed/error), expandable szczegóły
  • Plan Message: specjalny format dla Plan mode — lista kroków z checkboxami, każdy krok może być expanded (pokazuje szczegóły)
  • System Message: center, muted, italic (np. "Agent started worktree session on branch ai/feature-auth")

Code Blocks w Wiadomościach

Każdy blok kodu w markdown ma:

  • Header: nazwa języka (badge) + nazwa pliku (jeśli podana) + Copy button
  • Syntax Highlighting: Monaco Editor w read-only mode (albo Prism.js jako fallback)
  • Line numbers: opcjonalne (toggle w ustawieniach)
  • Diff highlighting: jeśli blok zawiera diff (linie z + i -), pokoloruj zielono/czerwono
  • "Apply" button: jeśli code block to zmiana do pliku, przycisk "Apply to file" (aplikuje zmianę do repozytorium)

Input Area

Na dole panelu chatu:

  • Textarea: auto-resize (min 1 linia, max 10 linii), placeholder: "Ask the agent to do something..."
  • Attach button: paperclip icon, pozwala dołączyć pliki jako kontekst (drag & drop też działa)
  • Send button: arrow icon, wysyła wiadomość (disabled gdy empty)
  • Stop button: square icon, pojawia się gdy agent generuje odpowiedź (przerywa generation)
  • "@" mention: wpisanie "@" otwiera autocomplete z skillami i plikami projektu
  • Keyboard: Enter = send, Shift + Enter = nowa linia

2.5. Diff Viewer i Code Review

Diff Viewer

Komponent do przeglądania zmian (jak GitHub diff):

  • Tryby widoku: Split (side-by-side) | Unified (jedna kolumna, jak git diff) — toggle w headerze
  • Lista plików: sidebar po lewej z listą zmienionych plików (nazwa, liczba + i - linii)
  • Code highlighting: dodane linie na zielono (+), usunięte na czerwono (-), kontekst normalnie
  • Inline comments: można dodać komentarz do konkretnej linii (dla AI — "zmień to na...")
  • "Stage chunk" button: przy każdym hunk diffa przycisk "Stage" (dodaje do commitu) lub "Revert" (cofa zmianę)
  • Navigation: przyciski prev/next file, prev/next hunk
  • Full file view: opcja "View full file" — pokazuje cały plik z podświetlonymi zmianami

Review Changes Panel

Gdy agent zakończy pracę, pojawia się panel review:

  • Podsumowanie: ile plików zmienionych, ile + i - linii, lista zmian
  • Commit message: auto-generowane przez AI (edytowalne)
  • Przyciski akcji:
    • Commit: zapisuje zmiany w worktree
    • Commit & Push: commit + push do remote
    • Commit, Push & Create PR: jednym kliknięciem — commit, push, otwiera przeglądarkę z nowym PR (pre-filled title i description)
    • Discard: usuwa zmiany i worktree
    • Continue: agent kontynuuje pracę (dodatkowe zmiany)

2.6. Zintegrowany Terminal

Terminal Panel

Zintegrowany terminal na dole/do boku głównego panelu (jak VS Code):

  • xterm.js jako renderer (WebGL acceleration)
  • Pty (pseudo-terminal) zarządzany przez Rust backend
  • Shell: używa domyślnego shella użytkownika (zsh, bash, fish, powershell)
  • Working directory: auto-ustawiane na root projektu (lub worktree)
  • Tabs: można mieć wiele terminali (plus icon w headerze)
  • Quick commands: przyciski do częstych komend (np. "npm test", "npm run build", "git status")
  • AI integration: można wybrać tekst w terminalu i wysłać do AI jako prompt ("explain this error", "fix this")

2.7. System Trybów Pracy

Chat Mode

Tryb dla szybkich pytań i iteracji:

  • Agent odpowiada bez planowania (direct response)
  • Nie tworzy planu, nie modyfikuje plików automatycznie
  • Może czytać pliki (jeśli pytanie o kod), ale nie pisze
  • Idealny do: "co robi ta funkcja?", "jak zaimplementować X?", "review tego kodu"
  • Streaming odpowiedzi token-by-token

Plan Mode

Tryb dla złożonych zadań wymagających planowania:

  • Agent najpierw analizuje codebase i generuje plan krok-po-kroku
  • Plan jest wyświetlany jako lista kroków z checkboxami
  • Użytkownik może edytować plan przed rozpoczęciem (dodawać/usuwać/zmieniać kroki)
  • Po akceptacji planu, agent wykonuje go krok po kroku
  • Każdy krok może być zatwierdzony indywidualnie (w trybie Supervised)
  • Idealny do: "dodaj system autentykacji", "zrefaktoryzuj ten moduł", "dodaj testy do X"

Worktree Mode

Izolowane środowisko pracy:

  • Agent pracuje w oddzielnym Git worktree (osobny katalog, osobny branch)
  • Twój główny workspace nie jest modyfikowany
  • Możesz kontynuować pracę na main branch podczas gdy agent pracuje na swoim branchu
  • Po zakończeniu: diff + review + merge/PR
  • Auto-cleanup: worktree jest usuwane po discard lub merge

Local Mode

Praca bezpośrednio w repozytorium:

  • Agent modyfikuje pliki bezpośrednio w Twoim workspace
  • Szybszy (brak overheadu worktree)
  • Ryzykowniejszy (brudzi workspace)
  • Recommended tylko w trybie Supervised

2.8. System Skili i Quick Actions

Skills (Reusable Prompts)

System gotowych, reuzywalnych promptów:

  • Definicja skilla: nazwa, opis, system prompt, dostępne tool'e, model
  • Wbudowane skille:
    • @react-component — "Stwórz komponent React z TypeScript"
    • @api-endpoint — "Dodaj endpoint API z walidacją"
    • @test-writer — "Napisz testy jednostkowe dla tej funkcji"
    • @refactor — "Zrefaktoryzuj ten kod"
    • @docs — "Wygeneruj dokumentację dla tego modułu"
    • @security — "Przeskanuj kod pod kątem bezpieczeństwa"
    • @optimize — "Zoptymalizuj wydajność tego kodu"
  • Użycie: wpisz @nazwa-skilla w inpucie chatu, auto-complete pokazuje dostępne skille
  • Custom skille: można tworzyć własne skille w managerze (Settings > Skills)
  • Skill Manager: lista skilli z opisem, edytor promptów, test playground

Quick Actions

Przyciski do natychmiastowego wykonania komendy shell:

  • Definicja: nazwa, komenda shell, keybinding (opcjonalny), auto-run flag
  • Przykłady: "Run Dev Server" (npm run dev), "Run Tests" (npm test), "Format" (npm run format), "Lint" (npm run lint)
  • Auto-run: można ustawić, żeby komenda uruchamiała się automatycznie po utworzeniu worktree (np. npm install)
  • UI: przyciski w toolbarze wątku, można dodawać/edytować/usuwać

2.9. Integracja Git i PR

Git Operations

  • Auto-detekcja: każdy projekt jest skanowany pod kątem repozytorium Git
  • Branch indicator: w sidebarze przy projekcie — aktualny branch
  • Git status: ile zmienionych plików, ile staged, ile untracked — badge
  • Commit: auto-generowany message (przez AI) lub manualny, modal z listą zmian
  • Push: push do remote z obsługą błędów
  • Create PR: otwiera przeglądarkę z pre-filled PR (title, description z changes summary)

Worktree Management

  • Auto-create: przy tworzeniu wątku w worktree mode, auto tworzy branch ai/[nazwa-wątku]
  • Auto-cleanup: przy discard wątku, usuwa worktree i branch
  • Worktree list: można zobaczyć wszystkie worktree w ustawieniach projektu

2.10. Ustawienia i Konfiguracja

Settings Pages

  • General: język UI, theme (dark/light/system), font size, line height
  • AI Models: lista skonfigurowanych modeli — dodawanie API keys (OpenAI, Anthropic), konfiguracja Ollama (URL, modele), default model per project
  • Skills: manager skilli — lista, edytor, test playground, import/export
  • Projects: lista dodanych projektów, default settings per project
  • Keyboard Shortcuts: konfiguracja skrótów klawiszowych
  • Advanced: max tokens, temperature default, timeouty, log level, data directory

Flow Danych (Przykład)

Użytkownik wysyła prompt w chatcie:

  1. Frontend (React): sendMessage(content, threadId) wywołuje invoke("llm_chat", payload)
  2. Tauri IPC: serializuje payload do JSON, przesyła do Rust
  3. Rust llm_chat command:
    1. pobiera historię z SQLite,
    2. buduje kontekst (system prompt + attached files),
    3. liczy tokeny,
    4. wysyła request HTTP do API (OpenAI/Anthropic/Ollama) z streaming (SSE)
  4. Rust streamuje odpowiedź: każdy token jest wysyłany jako event przez app_handle.emit("llm_token", token)
  5. Tauri IPC: event jest przesyłany do frontendu
  6. Frontend (React): odbiera event przez listen("llm_token", handler) i appenduje token do wiadomości
  7. Po zakończeniu: Rust zapisuje pełną odpowiedź do SQLite

Każdy tool call jest wyświetlany w chacie jako specjalna wiadomość (tool call card): nazwa toolu, parametry (JSON), status (running/completed/error), wynik (zwijany). Timeout: 30s per tool call. Error handling: retry lub przerwanie.

TASK 8.5: Human-in-the-Loop (Supervised Mode)

Gdy wątek jest w Supervised mode: przed każdą operacją piszącą (write_file, run_command destrukcyjne) agent zatrzymuje się i czeka na akceptację. Modal "Action Required": opis akcji, podgląd zmian (diff), przyciski "Approve" (kontynuuj), "Reject" (pomiń), "Edit" (zmień i approve). Timeout: 10 minut (po czym anuluje). Wszystkie oczekujące akcje są persistowane (można zamknąć i wrócić do aplikacji).
